# 变量与变量的应用学习笔记

## 1. 变量的定义与赋值

**变量**（variable）是程序里存放数据的容器，可以想成一个贴了名字标签的盒子：标签是变量名，盒子里的东西是值，能装什么由类型决定。

### 核心概念

| 要素 | 含义 | 例子 |
| ---- | ---- | ---- |
| 类型（type） | 决定能装什么数据、占多大空间 | `int`、`double` |
| 名字（name） | 访问这个盒子的凭据 | `age`、`score` |
| 值（value） | 盒子里当前存放的数据 | `20`、`95.5` |

- **定义**（definition）：申请一个盒子并起名
- **初始化**（initialization）：定义的同时放入第一个值
- **赋值**（assignment）：往已有的盒子里放新值，旧值被覆盖

### 语法格式

```cpp
数据类型 变量名;              // 只定义
数据类型 变量名 = 初始值;      // 定义并初始化
```

### 代码示例

```cpp
int age;                  // 只定义
age = 20;                 // 之后赋值

double score = 95.5;      // 定义并初始化
int a = 1, b = 2, c = 3;  // 一次定义多个同类型变量
int sum = a + b;          // 用表达式的结果初始化

a = 5;                    // 直接改值
a = a + 10;               // 计算后赋值：先算右边得 15，再存回 a
cout << sum << " " << a;  // 3 15
```

`a = a + 10;` 看着像数学里的矛盾等式，但赋值是**先算右边、再存左边**，所以完全合法，这也是累加写法的雏形。

### 易错点

1. 把 `=` 当数学等号 —— 它是**赋值运算符**（assignment operator），判断相等要用 `==`
2. 定义了没赋值就用 —— 未初始化的变量里是**垃圾值**（garbage value），输出不可预测
3. 类型与值不匹配 —— `int x = 3.7;` 会截掉小数，`x` 实际是 `3`
4. 漏写分号 —— 定义和赋值语句末尾都要有 `;`

> **本节小结**：变量是「类型 + 名字 + 值」三要素构成的容器，`类型 名字 = 值;` 是定义并初始化的标准写法。赋值是「先算右边、再存左边」，用前必须先赋值。

## 2. 变量命名规则

变量名属于**标识符**（identifier），必须遵守四条硬规则，另外还有几条提升可读性的建议。

### 命名规则

1. **只能由字母、数字、下划线组成** —— `score`、`student_age`、`arr1` 合法，`my-array`、`arr@1` 非法
2. **不能以数字开头** —— `arr1` 合法，`1arr`、`2nd` 非法
3. **不能是 C++ 关键字**（keyword）—— `int`、`double`、`char`、`bool`、`return`、`if`、`for`、`while` 都不行
4. **区分大小写** —— `age`、`Age`、`AGE` 是三个不同的变量

### 合法与非法对比

| 变量名 | 是否合法 | 原因 |
| ---- | ---- | ---- |
| `student_score` | 合法 | 符合全部规则 |
| `_count` | 合法 | 可以用下划线开头 |
| `1arr` | 非法 | 数字开头 |
| `my-array` | 非法 | 含减号 |
| `int` | 非法 | 是关键字 |
| `总成绩` | 非法 | 不能用中文字符 |

### 命名建议

- **见名知意**：`age` 表示年龄、`score` 表示分数，不要用 `a`、`b` 当主要变量
- **多单词拼接**：小驼峰 `studentName`、`totalScore`，或下划线 `student_name`
- **避开关键字变体**：`Int`、`INT` 虽然合法，但极易看错，不要用

> **本节小结**：变量名只能由字母、数字、下划线组成，不能数字开头、不能撞关键字、严格区分大小写；命名优先做到「见名知意」，这比写得短更重要。

## 3. 两个变量交换

交换两个变量的值是编程里的经典小问题，它能清楚暴露「赋值会覆盖旧值」这个特性。

### 错误的直觉写法

```cpp
int a = 3, b = 5;
a = b;   // a 变成 5，原来的 3 被覆盖，永久丢失
b = a;   // b 也变成 5，两个变量都成了 5
```

问题在于第一步就把 `a` 的旧值毁掉了，所以必须**先找个地方把旧值存起来**。

### 正确做法：借助第三方变量

```cpp
int a = 3, b = 5;
int tmp = a;    // 备份 a 的旧值
a = b;          // a 拿到 b 的值
b = tmp;        // b 拿到备份的旧值
cout << a << " " << b;   // 5 3
```

三步执行过程：

| 步骤 | `a` | `b` | `tmp` |
| ---- | ---- | ---- | ---- |
| 初始状态 | 3 | 5 | 未定义 |
| `tmp = a;` | 3 | 5 | 3 |
| `a = b;` | 5 | 5 | 3 |
| `b = tmp;` | 5 | 3 | 3 |

`tmp` 就是**临时变量**（temporary variable），交换完成后它的使命就结束了。

### 易错点

1. 直接写 `a = b; b = a;` —— 两个变量最后相等，旧值丢失
2. 备份顺序写反 —— 必须先 `tmp = a;` 再 `a = b;`，顺序颠倒就白备份了
3. 忘记给 `tmp` 定义类型 —— 要写 `int tmp = a;`，或先 `int tmp;`
4. 用加减法却忽略溢出 —— 两个接近 `int` 上限的数相加会翻转，实际编程推荐第三方变量法

> **本节小结**：交换两个变量必须借一个临时变量先备份，顺序是「备份 → 覆盖 → 还原」；直接互相赋值只会让两者变成同一个值。

## 4. 累加与计数

**累加**和**计数**是变量最常用的两种应用模式，几乎所有求和、统计类题目都建立在它们之上。

### 核心概念

| 模式 | 英文 | 作用 | 初值 |
| ---- | ---- | ---- | ---- |
| 累加器 | accumulator | 把一串数据加起来 | `0` |
| 计数器 | counter | 统计满足条件的个数 | `0` |
| 累乘器 | product | 把一串数据乘起来 | `1` |

三者的共同点是：**变量自己参与运算，结果再存回自己**，写法都是 `变量 = 变量 运算 数据;`。

### 代码示例

```cpp
int sum = 0;       // 累加初值取 0
sum = sum + 85;    // 85
sum = sum + 92;    // 177
sum = sum + 79;    // 256

int cnt = 0;       // 计数初值取 0
cnt = cnt + 1;     // 1
cnt = cnt + 1;     // 2

int prod = 1;      // 累乘初值取 1
prod = prod * 2;   // 2
prod = prod * 3;   // 6

cout << sum << endl;        // 256，总分
cout << sum / 3 << endl;    // 85，整数除法把小数截掉了
cout << sum / 3.0 << endl;  // 85.3333，需要小数时写 3.0
cout << cnt << " " << prod; // 2 6
```

初值为什么这样选：`0` 加上任何数都不改变结果，是加法的「不影响单位」；而乘法的单位是 `1`，初值写 `0` 会让结果永远是 `0`。

### 易错点

1. 累加初值写成 `1` —— 结果会凭空多出 `1`
2. 累乘初值写成 `0` —— 无论乘什么结果永远是 `0`
3. 只写 `sum + 85;` 漏掉 `sum =` —— 表达式算完就被丢弃，`sum` 一点没变
4. 求平均时被整数除法截断 —— `256 / 3` 得 `85`，想要小数得写 `3.0`

> **本节小结**：累加与计数都是「变量自己参与运算再存回自己」，关键在初值：累加取 `0`、计数取 `0`、累乘取 `1`。掌握了这个模式，后续循环里的求和统计就是水到渠成。

## 5. 变量的作用与生命周期

变量并不是在任何位置都能用。能被使用的范围叫**作用域**（scope），从创建到销毁的这段时间叫**生命周期**（lifetime）。

### 核心概念

- **局部变量**（local variable）：定义在函数内部或某一对大括号 `{}` 内部，只在该范围内有效
- **全局变量**（global variable）：定义在所有函数之外，整个程序都能访问（后续课程会专门讲）
- 大括号结束，里面定义的局部变量立刻被销毁，内存被回收
- **遮蔽**（shadowing）：内层定义了与外层同名的变量，内层的会临时挡住外层的

### 代码示例

```cpp
int main()
{
    int a = 10;          // 在 main 的整个范围内有效
    {
        int b = 20;      // 只在这个大括号内有效
        cout << a + b;   // 30，内层可以使用外层的变量
    }
    // cout << b;        // 错误：b 已随大括号结束而销毁
    cout << a;           // 10，a 依然有效
    return 0;
}
```

### 使用建议与易错点

1. **就近定义**：在真正要用它的地方附近定义，别一股脑堆在开头
2. **先赋值再用**：局部变量不初始化就是垃圾值，读出来毫无意义
3. **避免同名**：内外层用同名变量极易看错，例如内层写 `int x = 2;` 只是挡住外层的 `x`，外层那个 `x` 一点没变
4. **别跨作用域使用**：在大括号外使用里面定义的变量，编译会报「未声明」

> **本节小结**：作用域由变量所在的大括号决定，出了大括号变量即失效；内层同名变量只遮蔽外层而不修改它。就近定义、先赋值后用、少用同名，能躲开大量莫名其妙的错误。

## 知识框架梳理

### 核心概念总结

- **变量**：存放数据的容器，由类型、名字、值三要素构成
- **定义 / 初始化 / 赋值**：申请盒子 / 定义时放值 / 之后覆盖旧值
- **赋值运算符 `=`**：先算右边再存左边，不是数学等号
- **标识符规则**：字母数字下划线、不能数字开头、不能是关键字、区分大小写
- **交换变量**：必须借临时变量，顺序是「备份 → 覆盖 → 还原」
- **累加与计数**：变量自己参与运算再存回自己，累加初值 `0`、累乘初值 `1`
- **作用域与生命周期**：由大括号决定，出了范围变量即销毁
- **遮蔽**：内层同名变量挡住外层，但不修改外层

### 语法速查表

| 用途 | 写法 | 示例 |
| ---- | ---- | ---- |
| 定义变量 | `类型 变量名;` | `int age;` |
| 定义并初始化 | `类型 变量名 = 值;` | `int age = 20;` |
| 一次定义多个 | `类型 a = 1, b = 2;` | `int a = 1, b = 2;` |
| 赋值 | `变量名 = 值;` | `age = 25;` |
| 计算后赋值 | `变量 = 变量 运算 值;` | `a = a + 10;` |
| 交换变量 | 借 `tmp` 三步 | `tmp=a; a=b; b=tmp;` |
| 累加 | `sum = sum + x;` | 初值 `0` |
| 累乘 | `prod = prod * x;` | 初值 `1` |

### 易错点提醒

1. **混淆 `=` 与 `==`**：赋值用 `=`，判断相等用 `==`
2. **未初始化就用**：局部变量不赋值就是垃圾值
3. **用关键字命名**：`int int = 1;` 编译失败
4. **中文变量名**：标识符只允许英文字母、数字、下划线
5. **大小写不一致**：`Sum` 和 `sum` 是两个变量
6. **交换时丢值**：先备份 `tmp = a;`，再覆盖 `a = b;`
7. **初值选错**：累加用 `0`，累乘用 `1`，写反结果全错
8. **漏写 `sum = `**：只写 `sum + 85;` 什么都不会发生
9. **跨作用域使用**：出了大括号，里面的变量已经不存在

> **本节小结**：变量是内存里一块有名字的存储，先定义再使用；交换靠临时变量，累加靠「初值 0、循环里 +=」。
