# 最大值与分支嵌套学习笔记

## 1. 两数最大值

### 核心概念

求最大值最朴素的想法叫**打擂台法**：先让第一个数站上擂台当擂主，后面每来一个数就比一比，谁大谁就当新擂主。比完所有数，站在擂台上的就是最大值。

这种"**先假设，再更新**"的写法比罗列所有大小情况更简单，也更容易扩展到更多个数。

### 核心写法：打擂台

只有两个数时，用双分支 `if (a > b)` 直接输出其中一个也行；但数值个数一变多，分支就写不过来了，所以要换成打擂台写法：

```cpp
int a, b, maxn;
cin >> a >> b;

maxn = a;          // 先假设 a 最大
if (b > maxn) {    // 后来的数挑战擂主
    maxn = b;      // 赢了就换人
}
cout << maxn << endl;
```

- `maxn` 专门存"当前最大值"，名字取自 max，避免与库函数重名
- `maxn = a;` 是**初始化假设**，不能漏
- `>` 决定方向：只有更大才更新

### 易错点

1. **忘记初始化 `maxn`** —— 里面是随机值，比较结果完全不可靠
2. **把 `>` 写成 `<`** —— 求最大值却换成了更小的数，最后得到最小值
3. **只在 `if` 里输出** —— 没有更新 `maxn`，这个结果无法继续参与后续比较

> **本节小结**：求最大值用"先假设第一个数是最大，再用 `if` 逐个挑战擂主"的打擂台法，关键在于初始化假设和更新方向。

## 2. 三数最大值

### 核心概念

三个数不能再用一次 `if-else` 解决，但打擂台思想可以直接沿用：**a 先当擂主，b 挑战一次，c 再挑战一次**。

### 代码示例

```cpp
#include <iostream>
using namespace std;

int main()
{
    int a, b, c, maxn;
    cin >> a >> b >> c;

    maxn = a;
    if (b > maxn) {
        maxn = b;
    }
    if (c > maxn) {
        maxn = c;
    }

    cout << maxn << endl;
    return 0;
}
```

### 执行过程追踪

| 输入 | 初始 maxn | b 挑战后 | c 挑战后 |
| ---- | --------- | -------- | -------- |
| `3 9 5` | 3 | 9（9 > 3） | 9（5 > 9 不成立） |
| `3 1 9` | 3 | 3（1 > 3 不成立） | 9（9 > 3） |

### 为什么两个 if 不能换成 else if

这是本节最关键的坑。第二个 `if` 必须**独立判断**：

```cpp
// 错误写法：用 else if 串联
maxn = a;
if (b > maxn)       maxn = b;
else if (c > maxn)  maxn = c;   // b 赢过一次后，c 再没机会挑战
```

输入 `1 2 0` 时，`b > maxn` 成立，进入第一个分支后**命中即停**，`c` 根本没被比较，而它明明是最大的。

**结论：每个数都要单独挑战一次，必须写多个独立的 `if`**；数更多时，把这一句"挑战"放进循环即可。

### 易错点

1. 用 `else if` 串联多次比较，导致部分数据没参与比较
2. 比较方向写反，`if (maxn > c) maxn = c;` 变成找最小值
3. 三个数用三层嵌套 `if`，能算对但远比打擂台写法复杂

> **本节小结**：三数最大值就是打擂台法跑两轮挑战，每个数都要用**独立的 `if`** 挑战当前擂主，绝不能用 `else if` 串起来。

## 3. 分支嵌套的写法

### 核心概念

**分支嵌套**（nested branch）指在一条分支语句的语句体里，又放了另一条分支语句，即"**分支语句里放了分支语句**"。

它用来表达**有先后依赖的判断**：第二个判断只有在第一个判断成立的前提下才有意义。

### 语法格式

```cpp
if (外层条件)
{
    if (内层条件)   // 外层成立才会走到这里
    {
        语句;
    }
}
```

### 执行顺序

**从上到下，从外到内，依次执行。**

- **从上到下**：外层语句体里的代码按书写顺序一条条执行
- **从外到内**：先判断外层条件，外层成立才进入内层，内层条件才被计算

```cpp
if (t <= 10) {
    a = 5;
    if (z == 1) {
        a = a + 5;
    }
}
```

若 `t = 20`，外层条件不成立，内层 `if` **连判断都不会做**，`a` 也不会被赋值。

### 代码示例：先及格再评优秀

```cpp
int score;
cin >> score;

if (score >= 60) {
    if (score >= 90) { cout << "优秀" << endl; }
    else             { cout << "及格" << endl; }
}
else {
    cout << "不及格" << endl;
}
```

"是否优秀"必须在"已经及格"的前提下讨论，所以内层 `if` 写在外层 `if` 里面才符合逻辑；如果几个条件彼此平级独立，就该改用多分支 `else if`。

### 易错点

1. **悬空 else**：`else` 永远与**最近的、还没配对的 `if`** 配对，和缩进无关
2. 内层 `if` 忘写大括号，外层本想配对的 `else` 被内层抢走
3. 把本可以平铺的判断硬写成嵌套，代码越写越深

> **本节小结**：分支嵌套就是"分支里再放分支"，执行时从上到下、从外到内，内层判断以外层条件成立为前提，`else` 与最近的 `if` 配对。

## 4. 嵌套的缩进与可读性

### 核心概念

**缩进**（indentation）指每进入一层结构就往右空出固定格数。缩进不改变运行结果，却直接决定别人（和几天后的自己）能不能看懂代码。

约定：**每嵌套一层多缩进 4 个空格**，同一层的语句左对齐。

### 缩进对比

```cpp
// 正确缩进：一眼看出谁属于谁
if (score >= 60) {
    if (score >= 90) {
        cout << "优秀";
    }
}

// 没有缩进：能运行，但看不出层次
if (score >= 60) {
if (score >= 90) {
cout << "优秀";
}
}
```

### 易错点：缩进骗人

缩进只是**给人看的**，编译器只认大括号：

```cpp
if (a > 0)
    if (b > 0)
        cout << "都为正";
else
    cout << "a 不为正";   // 这个 else 其实属于内层 if！
```

这里的 `else` 与**内层** `if (b > 0)` 配对，缩进骗了读者的眼睛。补上大括号就能消除歧义：

```cpp
if (a > 0) {
    if (b > 0) {
        cout << "都为正";
    }
}
else {
    cout << "a 不为正";   // 现在明确属于外层 if
}
```

### 降低嵌套深度的三个办法

1. **改写为多分支** —— 条件平级时用 `else if` 拉平
2. **合并条件** —— `if (a > 0) { if (b > 0) ... }` 可写成 `if (a > 0 && b > 0)`
3. **提前处理特殊情况** —— 先把边界情况处理掉，主逻辑就不必再包一层

> **本节小结**：缩进是给人和自己看的层次标记，每层 4 空格、同级左对齐、大括号不省，才能让 `else` 的归属一目了然。

## 知识框架梳理

### 核心概念总结

- **打擂台法**：先假设第一个数是最大值，再用 `if` 逐个比较更新
- **最大值变量 `maxn`**：必须初始化，方向是"更大的才更新"
- **独立 `if`**：求最值时每个数都要单独挑战，不能用 `else if` 串联
- **分支嵌套**：分支语句的语句体里再放分支语句
- **执行顺序**：从上到下、从外到内，内层依赖外层成立

### 语法速查表

| 用途 | 写法 |
| ---- | ---- |
| 打擂台初始化 | `maxn = a;` |
| 挑战更新 | `if (b > maxn) maxn = b;` |
| 三数最大值 | 初始化后接两个独立的 `if` |
| 分支嵌套 | `if (外层) { if (内层) { ... } }` |
| 消除歧义 | 内外层都加大括号 |
| 合并条件 | `if (a > 0 && b > 0)` |
| 缩进规范 | 每层 4 个空格 |

### 易错点提醒

1. `maxn` 忘记初始化，比较的是随机值
2. 比较方向写反，求最大值得到最小值
3. 用 `else if` 串联多次挑战，部分数据没参与比较
4. 悬空 `else`：与最近的 `if` 配对，与缩进无关
5. 内层 `if` 只用缩进不用大括号，外层 `else` 被抢走
6. 嵌套超过三层，逻辑难以维护
7. 求最值时在两个分支里各输出一次，结果无法继续使用

> **本节小结**：求最大值靠"假设 + 逐个挑战"的打擂台法，表达有依赖的判断靠分支嵌套；一个管逻辑正确，一个管结构清晰，两者都要配上正确的缩进和大括号。
