## 1. 整数除法与浮点除法

同样是除法，操作数的类型不同，结果可能天差地别。这是初学者最容易踩的坑之一。

### 核心概念

- **整数除法**（integer division）：两个操作数都是整数时，结果**只保留整数部分**，小数部分被直接丢弃
- **浮点除法**（floating-point division）：只要有一方是小数，结果就是小数，保留小数部分
- 丢弃小数部分叫**截断**（truncation），它**不是四舍五入**，`10 / 3` 得 `3` 而不是 `3.3333`

### 代码示例

```cpp
#include <iostream>
using namespace std;

int main()
{
    cout << 10 / 3 << endl;      // 3
    cout << 10 / 3.0 << endl;    // 3.33333
    cout << 9 / 3 << endl;       // 3
    cout << 3 / 5 << endl;       // 0，不够除直接是 0
    return 0;
}
```

`3 / 5` 得 `0` 特别值得记住：被除数比除数小的时候，整数除法的结果恒为 `0`。

### 易错点

1. 以为程序会自动四舍五入 —— 整数除法是**直接砍掉**小数，`7 / 2` 得 `3` 而不是 `4`
2. 用整数除法求平均分 —— 总分和人数都是整数时，平均分的小数部分会整个丢掉
3. 忘记「先算后转」—— `double x = 10 / 4;` 右边先算出整数 `2`，再变成 `2.0`，小数早就没了

> **本节小结**：整数除法的结果永远是整数，小数部分被直接丢弃而不是四舍五入。想要小数结果，必须让浮点数出现在除法之前。

## 2. 取余运算 `%`

取余运算符 `%` 用来求两数相除的**余数**（remainder），它是整数专属的运算符。

### 核心概念

- 语法：`a % b`，读作「`a` 对 `b` 取余」
- 含义：`a` 除以 `b` 之后**剩下多少**
- 关系式：`a % b = a - (a / b) * b`，即被除数减去商乘除数
- **只能用于整数**，`%` 两侧出现小数会直接编译报错

### 代码示例

```cpp
cout << 7 % 3;    // 1，因为 7 = 3*2 + 1
cout << 7 % 2;    // 1
cout << 8 % 2;    // 0，能整除余数为 0
cout << 15 % 4;   // 3
cout << 3 % 5;    // 3，被除数比除数小，余数就是它本身
```

### 常见用途

- **判断奇偶**：`n % 2` 余 `1` 为奇数，余 `0` 为偶数
- **判断整除**：`n % 3 == 0` 说明能被 3 整除
- **数位分离**：`n % 10` 取个位，`n / 10` 去掉个位，两者配合可以从后往前拆数字
- **限定范围**：`i % 7` 的结果始终落在 `0 ~ 6` 之间

### 易错点

1. 对小数取余 —— `7.5 % 2` 编译失败，`%` 只接受整数
2. 除数为 `0` —— `7 % 0` 和 `7 / 0` 都会导致程序崩溃，写之前要确认除数不为零
3. 把 `%` 当成百分号 —— C++ 中百分号只表示取余，不表示百分比
4. 混淆 `%` 与 `/` —— `123 % 10` 得 `3`（个位），`123 / 10` 得 `12`（去掉个位）

> **本节小结**：`%` 求的是除完剩下的余数，只能用于整数，`a % b` 的结果范围是 `0` 到 `b-1`。判断奇偶、判断整除、取个位数字，都靠它。

## 3. 负数取余

被除数或除数带负号时，余数的符号有明确规则，不弄清楚就会写出看似正确、实际错误的条件判断。

### 核心概念

C++ 规定：**余数的符号与被除数相同**，与除数的符号无关。

推导依据仍是那条关系式：`a % b = a - (a / b) * b`，其中 `a / b` 向零截断。

| 被除数 | 除数 | 商 | 余数 |
| ---- | ---- | ---- | ---- |
| `7` | `3` | `2` | `1` |
| `-7` | `3` | `-2` | `-1` |
| `7` | `-3` | `-2` | `1` |
| `-7` | `-3` | `2` | `-1` |

可以看到：只要被除数是负数，余数就是负数或零；被除数是正数，余数就是正数或零。

### 代码示例

```cpp
cout << 7 % 3;     // 1
cout << -7 % 3;    // -1
cout << 7 % -3;    // 1
cout << -7 % -3;   // -1
cout << -8 % 2;    // 0，能整除时没有符号问题
```

### 负数余数转正

需要得到数学意义上的非负余数时，用 `(a % b + b) % b` 换算：

```cpp
int a = -7, b = 3;
cout << a % b;                 // -1
cout << (a % b + b) % b;       // 2，转成了非负余数
```

### 易错点

1. **用 `== 1` 判断奇数** —— `-3 % 2` 得 `-1`，`-3 % 2 == 1` 为假，会把负奇数误判成偶数。正确写法是 `n % 2 != 0`
2. 以为取余结果总是非负 —— 只有在被除数非负时才成立
3. 用绝对值硬凑 —— 先取绝对值再取余，会丢掉原本的符号信息，不如直接套换算公式

> **本节小结**：负数参与取余时，余数的符号跟着**被除数**走。判断奇数务必写 `n % 2 != 0`，不要写 `n % 2 == 1`。

## 4. 计算机基础

写程序本质上是在指挥计算机处理数据，了解数据在机器里怎么表示，很多「奇怪」的现象就能解释通了。

### 二进制

- **二进制**（binary）：只用 `0` 和 `1` 两个数字，逢二进一
- 计算机内部用高电平表示 `1`、低电平表示 `0`，二进制正好对应这两种状态
- 同一个数在十进制和二进制下的写法不同：十进制的 `5` 是二进制的 `101`

### 位与字节

- **位**（bit，缩写 b）：最小存储单位，一位就是一个 `0` 或一个 `1`
- **字节**（byte，缩写 B）：`8` 位组成 `1` 字节，字节是内存编址的基本单位
- 换算关系：`1 B = 8 bit`，`1 KB = 1024 B`，`1 MB = 1024 KB`，`1 GB = 1024 MB`

`n` 位二进制一共能表示 `2^n` 种组合。8 位无符号数可以表示 `0 ~ 255` 共 256 个值。

### 内存

把**内存**（memory）想象成一排带编号的小格子：

- 每个格子容量是 `1` 字节
- 每个格子有唯一编号，这个编号叫**地址**（address）
- 程序通过地址找到格子，再从格子里取出或写入数据
- `char` 占 1 字节，正好装满一个格子；`int` 占 4 字节，要连占 4 个格子
- `long long` 与 `double` 各占 8 字节，所以 `int` 换成 `long long` 会多用一倍内存

> **本节小结**：计算机用二进制表示一切数据；位是最小单位，8 位为 1 字节；内存是编址的字节格子，每个变量都要占用若干个格子。

## 5. 数据在内存中的存储

一个变量其实包含三样东西：**类型**、**名字**、**地址**。类型决定了它占几个字节，以及这一串 `0/1` 该如何解释。

### 类型决定解释方式

同一段 `0/1` 数据，按 `int` 读出来是一个整数，按 `char` 读出来是某个字符。**类型是解读内存的说明书**，同一段数据换了说明书，含义就变了。

### 整数用补码存储

整数在内存中以**补码**（two's complement）形式存放：

- 正数：补码与原码相同，最高位为 `0`
- 负数：把对应正数按位取反再加一，最高位为 `1`

正因为最高位被用来表示符号，`int` 能表示的范围并不对称：

| 类型 | 取值范围 |
| ---- | ---- |
| `int` | `-2147483648 ~ 2147483647` |
| `long long` | `-9223372036854775808 ~ 9223372036854775807` |

负数比正数多一个，多出来的那个就是 `-2147483648`。

### 溢出

**溢出**（overflow）指计算结果超出了类型能表示的范围。数值到达最大值后再加一，会翻转成最小值，像钟表走到 12 点又回到 1 点。

```cpp
#include <iostream>
#include <climits>
using namespace std;

int main()
{
    int a = INT_MAX;
    cout << a << endl;        // 2147483647
    cout << a + 1 << endl;    // -2147483648，发生溢出
    return 0;
}
```

溢出的正确做法是**换用更大的类型**，而不是依赖翻转结果。

### 浮点数的存储

浮点数按 **IEEE 754** 标准存储，把 64 位拆成符号位、指数位、尾数位三部分。由于尾数位数有限，很多十进制小数无法被精确表示，`0.1 + 0.2` 的结果并不严格等于 `0.3`。这就是精度误差的来源，也是不能直接用 `==` 比较两个浮点数的原因。

### 易错点

1. 认为内存里存的是一位一位的十进制数字 —— 内存里只有 `0` 和 `1`
2. 认为 `1 KB = 1000 B` —— 计算机中按 `1024` 换算
3. 忽略类型范围硬算 —— 大数相乘前要先估算结果会不会超过 `int` 上限
4. 认为浮点数能精确保存任意小数 —— 二进制无法精确表示大部分十进制小数

> **本节小结**：变量由类型、名字、地址三要素构成，类型决定字节数与解读方式。整数以补码存储因而范围不对称，超范围会溢出；浮点数按 IEEE 754 存储因而存在精度误差。

## 知识框架梳理

### 核心概念总结

- **整数除法**：两边都是整数时结果截断取整，不四舍五入
- **取余 `%`**：求除完剩下的余数，只接受整数，结果范围 `0 ~ b-1`
- **负数取余**：余数符号与被除数一致，判奇数要写 `n % 2 != 0`
- **二进制**：只用 `0` 和 `1`，逢二进一，是计算机的底层表示
- **位与字节**：`1 B = 8 bit`，`1 KB = 1024 B`
- **内存**：按字节编址的格子，地址是格子的编号
- **补码**：整数的存储形式，使 `int` 的范围负数比正数多一个
- **溢出**：超出类型范围后数值翻转，应换用更大的类型

### 语法速查表

| 用途 | 写法 | 示例与结果 |
| ---- | ---- | ---- |
| 整数除法 | `a / b` | `10 / 3` 得 `3` |
| 浮点除法 | `a / 3.0` | `10 / 3.0` 得 `3.33333` |
| 取余 | `a % b` | `7 % 3` 得 `1` |
| 判断整除 | `a % b == 0` | `9 % 3 == 0` 为真 |
| 判断奇数 | `n % 2 != 0` | `-3 % 2 != 0` 为真 |
| 取个位 | `n % 10` | `123 % 10` 得 `3` |
| 去掉个位 | `n / 10` | `123 / 10` 得 `12` |
| 余数转非负 | `(a % b + b) % b` | `-7` 对 `3` 得 `2` |
| 整型上限 | `INT_MAX` | 需 `#include <climits>` |

### 易错点提醒

1. **整数除法截断**：`7 / 2` 得 `3`，不是 `4`
2. **除法时机**：`double x = 10 / 4;` 得 `2.0`，小数在除法时已丢失
3. **`%` 只用于整数**：`7.5 % 2` 编译失败
4. **除数为零**：`a / 0` 和 `a % 0` 都会让程序崩溃
5. **负数余数符号**：`-7 % 3` 得 `-1`，不是 `2`
6. **奇数判断**：写 `n % 2 != 0`，不要写 `n % 2 == 1`
7. **单位换算**：`1024` 进位，不是 `1000`
8. **溢出不可依赖**：超出范围就换 `long long`，不要指望翻转结果

> **本节小结**：整数除法只留整数部分、取余给出余数且符号随被除数——这两条规则直接决定了后面所有数位类题目的写法。
