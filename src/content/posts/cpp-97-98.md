## 1. 原码

### 为什么需要符号位

计算机内部只有 `0` 和 `1`，没有负号。要表示负数，只能**腾出一位专门当符号**：约定最高位是符号位，`0` 表示正、`1` 表示负，剩下的位放绝对值。

### 原码的定义

原码（sign-magnitude）就是"符号位 + 数值位"：**符号位**在最高位，0 正 1 负；**数值位**是其余各位，放绝对值的二进制。以 8 位为例：

| 数值 | 符号位 | 数值位（7 位） | 原码 |
| ---- | ---- | ---- | ---- |
| +24 | 0 | 0011000 | `00011000` |
| -24 | 1 | 0011000 | `10011000` |

正负只差最高位，数值部分完全一样，这是原码最直观的地方。

### 原码转十进制

两步：① 看最高位定正负；② 数值位按权展开累加。以 `1 0011000` 为例：符号位是 `1`，结果为负；数值位 `0011000` = 16 + 8 = 24，所以这个原码表示 `-24`。

### 同一串 0/1，读法不同结果不同

`10011000` 这 8 位，当**无符号二进制**读是 `128 + 16 + 8 = 152`，当**8 位原码**读则是 `-24`。所以"这串二进制等于几"必须先约定编码方式。C++ 的 `int` 用的是**补码**，不是原码。

### 原码的两个硬伤

1. **两个零**：`+0` = `00000000`，`-0` = `10000000`，同一个 0 有两种写法，判等时要额外处理
2. **加法不成立**：`1 + (-1)` 直接加得 `00000001 + 10000001 = 10000010`，按原码读是 `-2`，不是 0

计算机只会做加法，减法要靠"加上一个负数"实现。原码连 `1 + (-1)` 都算不对，所以必须换一种编码。

### 易错点

1. **符号位不参与数值计算**：原码转十进制时符号位只定正负，不能当 128 一起加
2. **位数固定**：8 位、16 位、32 位的原码写法不同，讨论前先说明位宽
3. **`-0` 不是另一个值**：它在数学上就是 0，只是编码上多占了一种组合

> **本节小结**：原码用最高位当符号位、其余位放绝对值，直观但有两个零、不能直接相加，这正是后面要引入反码和补码的原因。

## 2. 反码与补码

### 反码的规则

反码（ones' complement）分两种情况：**正数**的反码与原码**完全相同**；**负数**的符号位不变，其余各位**取反**（0 变 1、1 变 0）。

| 数值 | 原码 | 反码 |
| ---- | ---- | ---- |
| +21 | `00010101` | `00010101` |
| -21 | `10010101` | `11101010` |

负数的反码就是"符号位保持 1，数值位逐个翻转"，机械操作，不用重新算绝对值。

### 反码解决了什么、没解决什么

解决了负数转换的统一性，但仍有 `+0`（`00000000`）和 `-0`（`11111111`）两个零；而且 `1 + (-1)` 得 `00000001 + 11111110 = 11111111`，按反码读是 `-0`，得到的是负零而不是正零。反码与补码之间差的正是这个"1"：在反码上加 1，就得到补码。

### 补码的规则

补码（two's complement）的规则只有一句：**负数的补码 = 反码 + 1**；正数的原码、反码、补码三码完全相同。以 `-24` 为例走一遍：

| 编码 | 二进制 | 怎么来的 |
| ---- | ---- | ---- |
| 原码 | `10011000` | 符号位 1 + 数值 24 |
| 反码 | `11100111` | 符号位不变，其余取反 |
| 补码 | `11101000` | 反码加 1 |

### 补码为什么能算对

再看 `1 + (-1)`：`00000001 + 11111111 = 1 00000000`。8 位存不下第 9 位，最高位的进位被**直接丢弃**，剩下 `00000000`，正好是 0。

本质上是"模 256 运算"：在 8 位世界里 `11111111` 等价于 `-1`，因为 `-1 ≡ 255 (mod 256)`。补码把减法变成"加一个很大的正数再溢出回绕"，所以计算机只需要一套加法器。

### 补码的零与表示范围

- `0` 只有一种写法 `00000000`，`10000000` 被"征用"表示 `-128`
- 8 位补码范围是 `-128 ~ 127`，负数比正数多一个
- 32 位 `int` 范围是 `-2³¹ ~ 2³¹ - 1`

### 补码转十进制

符号位是 `0`：直接按权展开。符号位是 `1`：**取反加 1 得到数值大小，再添负号**。以 `11101000` 为例，取反得 `00010111`，加 1 得 `00011000` = 24，所以是 `-24`。也可以把最高位当 `-128` 用：`-128 + 64 + 32 + 8 = -24`，两种算法结果一致。

### 易错点

1. **补码忘了加 1**：只取反得到的是反码，不是补码
2. **正数也去取反**：正数三码相同，不需要任何变换
3. **符号位跟着取反**：求反码、补码时符号位保持不变
4. **`-128` 没有原码**：8 位的 `-128` 只有补码 `10000000`

> **本节小结**：反码是负数取反、补码是反码加 1；补码让 0 唯一、让减法变加法，因此成为计算机存储整数的标准编码。

## 3. 左移 `<<`

### 运算符与写法

`a << n` 表示把 `a` 的二进制位整体向左移动 `n` 位，要求**左右两边都是整数**。它和输出语句里的 `<<` 是同一个符号，靠左操作数区分：

```cpp
int d = 20;
d = d << 1;      // 左右都是整数，<< 是位左移运算符
cout << d;       // 左边是 cout，<< 是输出流操作符
```

### 移位规则

把补码的二进制位整体左移 `n` 位，**高位丢弃，低位补 0**，再按补码读回十进制。正数的原码和补码相同，所以正数左移看起来就是"原码左移、右边补 0"。

`a = 20`，补码是 `00010100`：

| 表达式 | 移位结果 | 十进制 | 与乘法对照 |
| ---- | ---- | ---- | ---- |
| `a << 1` | `00101000` | 40 | 20 × 2¹ |
| `a << 2` | `01010000` | 80 | 20 × 2² |

规律：**`a << n` = `a × 2ⁿ`**，左移 n 位相当于乘 2 的 n 次方。

### 负数左移

`-24` 的补码是 `11101000`，左移 1 位得 `11010000`。读回十进制：取反 `00101111`，加 1 得 `00110000` = 48，添负号为 `-48`，正好是 `-24 × 2`。可见补码的移位规则对正负数**完全统一**，不必为负数单独设计一套。

### 溢出：高位的代价

8 位世界里 `100` 的补码是 `01100100`，左移 2 位得到 `1 10010000`。最高位的 1 属于第 9 位，被直接丢弃，剩下 `10010000`，按补码读是 `-112`，而正确答案应该是 400。`int` 是 32 位，同样会在数字太大时悄悄溢出，所以用左移做乘法前要确认 `a × 2ⁿ` 没有超出范围。

### 用途与易错点

左移常用来快速乘 2 的幂（`x << 3` 就是 `x * 8`），以及构造位掩码 `1 << k`（只有第 k 位是 1 的数），为后面的与、或、异或做准备。

1. **和 `cout <<` 混淆**：看左操作数是不是流对象
2. **移位数超过位宽**：移动位数必须小于类型位宽，否则行为未定义
3. **忽略溢出**：高位被丢弃，结果可能变成负数
4. **优先级**：`<<` 优先级低于加法，混用要加括号，如 `(a + b) << 1`

> **本节小结**：左移是"补码整体左移、高位丢弃、低位补 0"，效果等于乘 2ⁿ，正负数规则统一，但要当心高位溢出。

## 4. 右移 `>>`

### 运算符与写法

`a >> n` 表示把 `a` 的二进制位整体向右移动 `n` 位，同样要求两边都是整数，也要和输入语句里的 `>>` 区分：

```cpp
int t = 60;
cin >> t;        // 左边是 cin，>> 是输入流操作符
t = t >> 1;      // 左右都是整数，>> 是位右移运算符
```

### 移位规则

把补码整体右移 `n` 位，**低位丢弃，高位补符号位**：正数高位补 0，负数高位补 1。这种"补符号位"的方式叫算术右移（arithmetic shift），它保证右移后符号不变。

`a = 60`，补码是 `00111100`：

| 表达式 | 移位结果 | 十进制 | 与除法对照 |
| ---- | ---- | ---- | ---- |
| `a >> 1` | `00011110` | 30 | 60 ÷ 2¹ |
| `a >> 2` | `00001111` | 15 | 60 ÷ 2² |
| `a >> 3` | `00000111` | 7 | 60 ÷ 2³ = 7.5 → 7 |

规律：**`a >> n` = `a ÷ 2ⁿ`，小数向下取整**。

### 为什么是向下取整

右移直接把最低的 n 位丢掉，等于把"不足 2ⁿ 的零头"全部舍掉，方向永远往小走，不是四舍五入。`7 >> 1` 中 7 ÷ 2 = 3.5，结果是 3 而不是 4；`60 >> 3` 中 60 ÷ 8 = 7.5，结果是 7。

### 负数右移

`-24` 的补码是 `11101000`，右移 1 位、高位补 1 得 `11110100`。读回：取反 `00001011`，加 1 得 `00001100` = 12，所以是 `-12`，正好等于 `-24 ÷ 2`。

再看 `-25`：补码 `11100111`，右移 1 位得 `11110011`，读回是 `-13`。而 `-25 ÷ 2 = -12.5`，向下取整正是 `-13`，与规律一致。

### 代码示例

```cpp
#include <iostream>
using namespace std;

int main()
{
    int t = 60;
    cout << (t >> 1) << " " << (t >> 2) << " " << (t >> 3) << endl;  // 30 15 7

    int x = -25;
    cout << (x >> 1) << endl;     // -13，不是 -12
    return 0;
}
```

### 用途与易错点

右移可用来快速除 2 的幂（`x >> 1` 就是 `x / 2`），二分查找取中点也常写 `mid = (l + r) >> 1`。

1. **和 `cin >>` 混淆**：看左操作数是不是 `cin`
2. **以为四舍五入**：右移是向下取整，`7 >> 1` 得 3
3. **以为负数右移得 0**：高位补 1，负数右移仍然是负数
4. **拿右移代替浮点除法**：它只对整数有意义，`5 >> 1` 是 2 不是 2.5
5. **移位数越界**：移动位数必须小于类型位宽

> **本节小结**：右移是"补码整体右移、低位丢弃、高位补符号位"，正数等价于除 2ⁿ 并向下取整，负数因补 1 而保持负号；左移乘、右移除，是同一套补码规则的两种方向。

## 知识框架梳理

### 核心概念总结

- **原码**：最高位符号位（0 正 1 负）+ 数值位，直观但有两个零、不能直接相加
- **反码**：正数同原码，负数符号位不变、其余取反，仍有 `+0`/`-0`
- **补码**：负数 = 反码 + 1，0 唯一、减法变加法，是计算机存储整数的标准
- **移位对象**：移的是**补码**而非原码，正负数遵循同一套规则
- **左移**：高位丢弃、低位补 0，等于 `× 2ⁿ`，注意溢出
- **右移**：低位丢弃、高位补符号位，等于 `÷ 2ⁿ` 向下取整，负数仍为负

### 语法速查表

| 用途 | 写法 / 规则 |
| ---- | ---- |
| 原码 | 符号位 + 绝对值二进制 |
| 负数反码 | 符号位不变，其余取反 |
| 负数补码 | 反码 + 1 |
| 原码转十进制 | 符号位定正负，数值位按权展开 |
| 补码转十进制 | 取反加 1 得数值，再添负号 |
| 8 位补码范围 | -128 ~ 127 |
| 左移 | `a << n`，等于 `a × 2ⁿ` |
| 右移 | `a >> n`，等于 `a ÷ 2ⁿ` 向下取整 |
| 快速乘 2 / 除 2 | `x << 1` / `x >> 1` |
| 构造掩码 | `1 << k` |
| 二分中点 | `(l + r) >> 1` |

### 易错点提醒

1. **补码少加 1**：取反只是反码，补码还要 +1
2. **符号位参与取反**：求反码、补码时符号位始终不变
3. **原码直接相加**：`1 + (-1)` 用原码算得 `-2`，必须用补码
4. **左移溢出**：高位被丢弃，大数左移会变成负数
5. **右移当四舍五入**：它是向下取整，`60 >> 3` 得 7
6. **`<<` / `>>` 认错身份**：左操作数是 `cout`/`cin` 时是流操作符，两边都是整数才是移位
7. **移位数越界**：移动位数必须小于类型位宽，否则行为未定义

> **本节小结**：原码、反码、补码是同一串二进制位的三种解释，补码因"零唯一、可加法"胜出并成为整数的存储方式；左移与右移正是对补码做整体平移，于是"左移乘 2ⁿ、右移除 2ⁿ 向下取整"这两条结论自然成立，代价是高位溢出与符号位补 1 这两个必须留意的细节。
